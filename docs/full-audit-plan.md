## 单条通过标准

1. 打开清单中的原链接，确认重定向后的页面确实属于对应作品；挑战页、404、错误页及与项目不相干的落点不能通过。
2. 确认主体图像、文本和关键控件已渲染，而非只出现标题、导航、空 Canvas、骨架屏或持续加载图标。
3. 按条目描述验证至少一个核心效果。自动动画应观察不同时间点的状态变化；滚动动效需实际滚动；拖拽、点击、悬停或键盘交互应执行对应操作并观察结果。无法验证的具体描述应收窄或标为未通过。
4. 视频需看见实际内容并确认播放进度变化，而非仅能读取元数据或封面。还需判断画面是否以作品展示为主，避免教程/宣传页漏网。无需完整观看长视频，但记录实际检查的片段和范围。
5. 完整网站需看到具有参考价值的 UI，并检查至少一个导航、展开、滚动或项目展示行为。只有营销文字的落点不应作为完整 UI 案例通过。
6. 页面内的公共预览可以通过；源码需要付费与预览本身受限应分别记录。遇登录、验证码、安全警告、GPU 不支持等限制，不绕过限制。

## 记录字段与判定

每条审阅记录至少包括清单编号、id、原链接、检查日期、主体观察、操作、操作结果、结论、原因及访问限制。按需附最终链接及替换建议。

- `pass`：已看到主体并验证与核心说明对应的效果；记录操作范围，不宣称测试全部交互。
- `remove`：确认实际页面错误、持续空白/加载、内容不符、教程主体或无可用视觉内容，移出主库。
- `blocked`：本环境无法完成核查，作为本次未通过处理；记录具体环境/访问限制，不写成“全网失效”。按用户对主库有效性的要求，不能继续标为已核验推荐。

HTTP 200、页面标题、HTML 包含 canvas/video、源码存在、曾经通过，均不能单独构成本次通过依据。
